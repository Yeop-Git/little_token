# Little Token

![타이틀 화면](docs/images/01-title.png)

단어를 하나씩 골라 문장을 완성하면, 그 문장이 그대로 전투 행동이 됩니다.
그림일기 테마의 단어장 덱빌딩 로그라이트입니다.

**▶ 플레이: <https://little-token-two.vercel.app>**

데스크톱 웹에서 1920×1080 기준으로 동작하며, TypeScript와 Vite로 만들었습니다.
15스테이지를 여정으로 삼고 5·10·15스테이지에 보스가 서며, 클리어하면 엔드리스가
이어집니다. 한국어와 영어, 일본어, 러시아어, 중국어 간체·번체를 지원합니다.

---

## 이 게임의 핵심

카드 하나하나의 수치는 크지 않습니다. 이 게임의 힘은 **단어를 어떻게
붙이느냐**에서 나옵니다. 한 문장을 확정할 때 여러 배율이 한꺼번에 곱해지기
때문입니다.

가장 먼저 눈에 들어오는 것은 **감정**입니다. 모든 단어는 기쁨·분노·슬픔·즐거움
중 하나를 품고 있고, 같은 감정을 한 문장에 모으면 공명이 일어납니다. 두 장이면
×1.15, 세 장이면 ×1.30이 되고, 그 뒤로 한 장을 더 얹을 때마다 0.15씩 더 자랍니다.
슬롯마다 감정별로 다섯 장씩 준비되어 있어서 어떤 감정을 밀고 가더라도 세 장
공명까지는 안정적으로 만들 수 있습니다. 그래서 단어장을 어느 감정으로 키울지
정하는 일이 그대로 빌드가 됩니다. 여기에 적의 체력바 옆에 뜬 약점 감정을 문장에
실으면 ×1.25가 더 붙습니다.

**관용구**는 그보다 한 단계 위의 보상입니다. 태그가 맞물리는 조합을 완성하면
「정면돌파」처럼 이름이 붙은 맥락이 발동하면서 큰 배율을 얹어 줍니다. 숨겨 둔
정답이 아니라, 조합이 성립하는 순간 이름과 수치가 화면에 그대로 드러납니다.

그리고 **배율에는 상한이 없습니다.** 감정 공명과 관용구가 겹쳐 쌓이면 한 문장이
적 하나를 훨씬 넘겨 때리게 되고, 넘친 피해는 사라지지 않고 다음 적에게 그대로
흘러갑니다. 줄지어 선 벌레들이 한 문장에 연쇄로 무너지는 순간이 이 게임이 노리는
쾌감입니다.

대신 자원이 있습니다. 문장 하나에 쓸 수 있는 **잉크**는 기본 6이고, 이전 문장에서
최대 2를 이월할 수 있습니다. 여기서 2까지 더 초과해 쓸 수 있지만 초과분은 확정할
때 체력으로 직접 지불해야 합니다. 큰 배율은 공짜가 아닙니다.

한 가지 지키는 원칙이 있습니다. **"고르면 손해"인 선택지는 두지 않습니다.**
실패 확률이나 자해, 부조화 패널티는 데이터에서 전부 걷어냈습니다. 선택지는 손해와
이득이 아니라 이득의 종류로 갈립니다. 격차는 나쁜 맥락에 벌점을 줘서가 아니라,
좋은 맥락에 큰 배수를 줘서 만듭니다.

## 구현된 흐름

### 오프닝 — 규칙을 설명 대신 손으로 익힙니다

![오프닝 대화](docs/images/02-intro.png)

주인공 **프롬**이 등장하는 오프닝입니다. 대사에 나온 단어가 그대로 "문장에 넣기"
카드가 되어, 첫 문장을 직접 조립해 보는 동안 규칙이 손에 익습니다. 급하면
SKIP으로 건너뛸 수 있습니다.

### 전투 — 한 턴은 문장 한 줄입니다

![전투 화면](docs/images/03-battle.png)

하단의 `1 주어 · 2 수식 · 3 동사` 슬롯을 왼쪽부터 채우면 문장이 완성되고, 완성된
문장이 그대로 판정됩니다.

상단에 뜬 관용구 `어제의 나는`은 75% 확률로 배율 ×1.80을 준다고 미리 알려 줍니다.
왼쪽 아래 잉크 4/10은 지금 이 문장에 얼마나 더 쓸 수 있는지, 초과하면 체력을
얼마나 낼지를 선택하는 내내 보여 줍니다. 왼쪽 위 행동 순서 패널은 이번 문장에서
나와 적 중 누가 먼저 움직이는지를 알려 주고, `살짝` 같은 수식어를 고르면 이 순서가
바뀝니다. 카드에 마우스를 올리면 오른쪽에 슬롯과 희귀도, 잉크 비용, 부가 효과가
펼쳐집니다. 함께 설 수 없는 조합은 뒤 단어를 잠그면서 그 이유까지 함께 보여 줍니다.

### 판정 — 숫자가 어디서 나왔는지 전부 보여 줍니다

![문장 판정 컷씬](docs/images/05-cutscene.png)

문장을 확정하면 컷인과 함께 계산 과정이 그대로 펼쳐집니다. 「정면돌파」 ×1.50,
「지난 일은 잊고」 ×1.55, 도박 ×1.80, 운 ×1.08이 곱해져 최종 배율 4.52가 되고,
그것이 32 피해로 떨어지는 과정을 하나도 숨기지 않습니다.

단어 상세도 같은 방식입니다. `흘린 잉크를 되마셨다`를 집으면 이 단어를 넣었을 때
문장의 최종 위력이 ×2.51이 된다는 것, 피해 +18에 잉크 3을 쓰고 1명을 공격하며
흡혈 50%가 붙는다는 것, 그리고 이 단어가 여는 「정면돌파」가 지금 발동 중이라는
것까지 확정하기 전에 미리 알려 줍니다. 배율을 노리는 판단이 도박이 아니라 계산이
되도록 만든 장치입니다.

### 보상 — 단어장이 곧 덱입니다

![보상 화면](docs/images/04-reward.png)

스테이지를 클리어하면 주어·수식어에서 하나, 아이템에서 하나, 동사에서 하나씩
세 번에 걸쳐 삼지선다를 고릅니다. 전투 등급이 그대로 재화인 **영감**이 되고,
카드 가격은 희귀도만 봅니다. 노멀 1, 희귀 2, 영웅 3, 전설 4입니다.

이미 가진 카드를 다시 고르면 반복강화로 단계가 오릅니다. 마음에 드는 게 없으면
영감 1을 내고 다른 발상을 떠올리거나, 그냥 넘어가도 됩니다. 층이 오를수록 높은
희귀도가 자주 나오고, 10층에서는 전설 아이템을, 15층에서는 전설 스킬을 하나씩
반드시 만나게 됩니다.

고르는 기준은 단순한 수치가 아닙니다. 내가 모으는 감정에 맞는 카드인지, 지금 가진
단어들과 새로운 관용구를 열어 주는지를 봅니다. 그게 이 게임의 덱빌딩입니다.

### 보스 — 전용 연출로 등장합니다

![보스 입장 컷씬](docs/images/06-boss-intro.png)

5·10·15스테이지에는 보스가 섭니다. 5층의 **사마귀**는 이렇게 전용 입장 연출과 함께
나타납니다.

### 보스 전투 — 적도 문장으로 예고합니다

![보스 전투](docs/images/07-boss-battle.png)

이 게임에서 가장 마음에 드는 대칭입니다. 적의 다음 행동도 플레이어와 똑같이 한 줄의
문장으로 조립되어 화면 한가운데 걸립니다.

> **사마귀가 / 온 힘을 모아 / 큰낫을 치켜든다**
> 이번 행동은 피해가 없고, 다음 문장은 큰낫 내려베기입니다.

이번 턴은 아무 일도 일어나지 않지만 다음 턴이 무엇인지는 알려 줍니다. 막을지, 먼저
때릴지, 자세를 무너뜨릴지를 그 한 줄을 읽고 결정하게 됩니다.

400/400짜리 체력바는 눈금으로 갈라져 있어 남은 막이 몇 개인지 한눈에 들어오고,
보스는 체력이 2/3과 1/3 경계를 지날 때마다 공격이 함께 무거워집니다. 왼쪽 패널은
사마귀가 선공으로 자세를 잡고 그다음에 프롬이 문장을 쓴다는 순서를 문장 시작 전에
확정해 보여 줍니다. 아이템 넉 점, 영감 14, 체력 60/68, 잉크 6/10 — 1스테이지에서
여기까지 온 흔적이 화면에 그대로 남아 있습니다.

### 그리고 런의 끝

보스를 넘기면 런 결과와 엔딩으로 이어지고, 클리어한 뒤에는 엔드리스가 열립니다.
패배 화면과 단어장, 가방, 관용구, 캐릭터 상세도 모두 연결되어 있습니다.

## 실행

기준 도구는 Node.js 24.18.1과 npm 11.16.0입니다. Node.js 24.18.0 이상 25 미만을
지원하며, 저장소 루트의 `.nvmrc`와 `package.json`을 로컬 개발과 배포가 함께
사용합니다.

```powershell
npm.cmd ci
npm.cmd run dev          # 개발 서버 (localhost:3000)
npm.cmd run dev -- --mode qa       # 정식판 QA: 필수 자원 실패를 즉시 보고
npm.cmd run dev -- --mode demo-qa  # 5스테이지 데모 QA
npm.cmd test             # 타입·데이터·현지화·전투·보스·밸런스 검사
npm.cmd run build        # 프로덕션 빌드 → dist/
npm.cmd run build:demo   # 5스테이지 데모 빌드 → dist-demo/
npm.cmd run release:check # 태그를 포함한 출시 전 전체 검사
```

출시 커밋 전에 같은 게이트를 미리 확인하고 싶다면
`npm.cmd run release:check -- --allow-dirty`를 사용합니다. 실제 출시 검사는 현재
버전의 annotated 태그가 HEAD를 가리키고 작업 트리가 깨끗해야 통과합니다.

데모판은 `.env.demo`의 `VITE_APP_EDITION=demo`로 5층 사마귀에서 완결됩니다. 설문
주소는 커밋하지 않는 `.env.demo.local`이나 배포 환경의 `VITE_FEEDBACK_URL`에
설정합니다. 정식 빌드는 15스테이지와 엔드리스를 유지하며, 두 에디션의 저장 데이터는
서로 분리됩니다.

`qa`와 `demo-qa` 모드는 이미지 디코딩과 GLB 파싱, 오디오·영상 로드 실패를 조용히
대체하지 않고 즉시 보고합니다. 일반 개발·배포 모드는 플레이가 멈추지 않도록 기존
2D·무음 폴백을 유지합니다. QA 수집기 자체를 시험하려면 `?qaMissingResource=image`를
붙여 누락 이미지가 실패로 기록되는지 확인할 수 있습니다.

CSV를 수정한 뒤에는 `npm.cmd run data:generate`를 실행합니다. 개발용 씬 직접 진입과
치트는 개발 빌드에서만 쓰입니다.

## 구조

```
src/core/          타입 · 문장 컴파일 · 검증 · 잉크 · 등급 예산 · 런 상태
src/data/          단어 · 관용구 · 감정 · 적 · 아이템 · 보상 · 스테이지
src/data/csv/      단어와 관용구의 정본 CSV
src/sim/           화면과 공유하는 전투 상태 변화 · 적 문장 생성
src/views/         화면 · 입력 · 연출 (타이틀 · 전투 · 보상 · 보스 · 엔딩)
src/localization/  한국어·영어·일본어·러시아어·중국어 간체·번체
src/tools/         전수 검사 · 보스 및 런 시뮬레이션
```

핵심 규칙이 어디에 있는지 찾을 때는 이 표를 봅니다.

| 알고 싶은 것 | 파일 |
|---|---|
| 배율이 곱해지는 순서 | `core/compiler.ts` |
| 감정 공명·약점 배율 상수 | `core/combatRules.ts` |
| 잉크와 초과 집필 | `core/ink.ts` |
| 희귀도별 성능 예산 | `core/budget.ts` |
| 단어의 감정 배치 | `data/emotions.ts` |
| 관용구 조합 | `data/combos.ts` |
| 오버킬 흘러넘침·부위 판정 | `sim/reference.ts` |

문장 슬롯은 길이가 고정되어 있지 않습니다. `data/slots.ts`의 템플릿을 바꾸면
덱이나 아이템이 칸을 더하거나 뺄 수 있고, 컴파일러는 슬롯 키를 하드코딩하지
않습니다.

단어와 관용구의 원본은 `src/data/csv/`에서 관리합니다. CSV를 고친 뒤에는
`npm run data:generate`를 실행하는데, 개발·검사·빌드 명령도 이 단계를 알아서
수행합니다. `src/data/generated/`는 생성물이므로 직접 손대지 않습니다.

밸런스는 문서가 아니라 코드가 강제합니다. `core/budget.ts`의 등급 예산을
`npm run check`가 CSV와 대조하고, `npm test`는 여기에 타입과 현지화, 전투 효과,
감정 밸런스, 아이템 밸런스, 보스 시뮬레이션, 런 시뮬레이션까지 한 번에 돌립니다.
