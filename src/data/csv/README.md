# 게임 데이터 CSV

문장 전투와 아이템 데이터의 원본이다. TypeScript 생성물을 직접 편집하지 않고 아래 CSV를 수정한다.

- `words.csv`: 일반 런, 보상, 확장용 단어
- `card_tactics.csv`: 일반 런 카드의 명시 잉크 비용과 수식어 전술 효과
- `combos.csv`: 관용구와 필요 태그 멀티셋
- `localized_combos.csv`: 언어별 전용 관용구, 현지 표현과 HTTPS 사전 출처
- `conflicts.csv`: 함께 사용할 수 없는 태그 쌍
- `dissonances.csv`: 허용하지만 성능이 감소하는 태그 쌍
- `items.csv`: 아이템 이름, 등급, 일러스트 키, 기본 스탯과 고유효과

## 아이템 규칙

`items.csv`는 `src/data/generated/itemData.ts`를 만든다. 노멀은 1점, 희귀는 2점의 고유 기본
스탯을 가지며 영웅·전설의 CSV 기본 스탯은 0이다. 획득할 때 감탄·정도·평가 3칸을 골라
선택 스탯을 받는다. 체력 +2·공격 +0.5·방어/회복/운 +1을 각각
1점으로 계산한다. 행운 감탄도 같은 가치표를 쓴다. 모든 선택은 최소 1점이고 등급 보너스는 노멀 0·희귀 1·영웅 2·전설 3점,
행운 감탄 전 최종 예산은 각각 3·4·5·6점이다. 보너스가 붙는 감탄 단계만 화면 입장 시
무작위로 정하며 총량은 변하지 않는다.
노멀·희귀는 고유효과가 없고, 영웅·전설은 선택 스탯에 문장 규칙을 바꾸는 `passive`가 추가된다.
생성기는 노멀/희귀와 영웅/전설의 수량 차가 각각 1개를 넘으면 실패해 등급 분포를 지킨다.

`pool`은 `early`(3슬롯 일반 런의 시작 패: 주어 2·수식어 3·동사 4), `reward`(획득 단어), `expansion`(확장 및 전수 검사),
`punct`(문장부호 · 올림프의 황금 당근), `grow`(보상용 무럭무럭) 중 하나다.
문장부호는 아이템이 여는 전용 카드풀이고, 무럭무럭은 보상으로 덱에 등록되는 성장 카드다.

무럭무럭 원본은 `slot`을 `*`로 두고 `grow` 행 하나만 유지한다. `earlyWords.ts`의
`growCardFor`가 초반 주어·수식·동사 보상 카드 세 장을 만들며, 수치와 등급이 같은지는
`npm run check`가 검사한다. 잭의 하늘나물 아이템은 이 카드를 복제하지 않고 전투당
첫 문장 완료 뒤 최대 체력 +1을 직접 적용한다.
한 셀에 여러 태그를 넣을 때는 `|`로 구분하고, 쉼표가 들어간 텍스트는 큰따옴표로 감싼다.

## 슬롯별 규칙

세 슬롯은 역할이 겹치지 않는다. 새 단어를 넣을 때 이 계약을 지킨다.

- **주어(subj)** — 배율 전용. `bonus`만 쓰고 `power`/`stat_mult`는 비운다.
  `person`은 필수: 일기의 주어는 1인칭뿐이라 `first`가 아니면 주어 슬롯에서 차단된다
  (`너는 힘껏 때렸다`가 애초에 조립되지 않는 이유). 2·3인칭은 목적어로 간다.
- **수식(adv)** — 행동을 즉시 바꾸는 전술 칸. `crit`·`stat`·`guard`·`heal`을 비우고,
  모든 행동에 가산되는 `bonus`와 선행·관통·연타·다중 대상·반격·동사 반복·초과 집필 연계를 조합한다.
  잉크 할인·추가 이월·적 공격 약화처럼 다음 장부를 외워야 하는 효과는 일반 수식어에 넣지 않는다. 뽑기 효과는 실제 `다시 뽑기` 횟수를 즉시 늘린다.
  방어와 회복의 실제 수치는 반드시 동사가 만든다. 수식어의 카운터도 방어를 직접 만들지 않고
  방어 동사를 골랐을 때만 의미가 생긴다.
  기능은 모두 이득의 종류이며 실패·자해 같은 디메리트는 넣지 않는다. 모든 일반 수식어에는
  공개 전술과 명시 잉크 비용이 최소 하나씩 있어야 한다.
- **동사(verb)** — 깡수치 전용. `stat` + `stat_mult`로 "공격 ×1 · 방어 ×1 · 회복 ×1"처럼
  스탯에 비례한 수치를 만든다(`power`는 스탯과 무관한 고정 위력이 필요할 때만).
  이 수치가 주어와 관용구의 배율을 받는다.

## 맥락 규칙 — 보상만 있고 벌은 없다

**어떤 조합이든 조립할 수 있고, 어색하다고 깎지 않는다.** 말이 안 되는 문장을 써도
손해는 없으니 마음대로 굴려 보고, 맞아떨어졌을 때만 크게 받는 구조다.

- `combos.csv` — **완벽한 맥락**. 태그가 맞아떨어지면 배율이 크게 오른다(초기 1.7~2.1).
  유일하게 살아 있는 맥락 규칙이라 값을 후하게 준다.
- `dissonances.csv` — 배율을 깎는 **어색한 맥락**. 지금은 비워 뒀다(디메리트 폐지).
- `conflicts.csv` — 조합 자체를 막는 하드 차단. 지금은 비워 뒀다.

두 파일의 처리 코드는 남아 있으니, 나중에 다시 벌칙을 넣고 싶으면 행만 채우면 된다.
유일하게 남은 차단은 주어의 `person` 계약(1인칭만 주어)이다.

주어 태그끼리는 한 문장에 함께 올 수 없으니 관용구는 `주어×수식`, `주어×동사`,
`수식×동사` 쌍으로만 만든다.

## 디메리트는 없다 — 등급은 "예산"이다

플레이어를 벌하지 않는다. **실패확률·자해·반동·부조화는 전부 폐지**했다.
`fail`, `recoil` 열은 비워 두고, `variance_lo`는 1 미만으로 내리지 않는다
(도박은 "가끔 크게 터진다"이지 "가끔 손해"가 아니다). 긴장은 카드가 아니라
**적의 체력과 공격**이 만든다.

대신 등급마다 **예산**이 있고, 카드는 그 총량을 어떻게 배분할지만 다르다.
같은 등급이면 강약이 아니라 **성향**이 갈리므로, 노멀도 끝까지 죽은 카드가 되지 않는다.
예산 값의 정본은 `src/core/budget.ts`이고 `npm run check`가 CSV를 그 값으로 검사한다.

| 등급 | 배율 칸 예산(주어·어미) | 동사 계수 |
|---|---|---|
| 노멀 (`common`) | 1.20 | ×1 |
| 희귀 (`rare`) | 1.60 | ×1.5 |
| 영웅 (`epic`) | 2.10 | ×2 |

- 주어 기대 배율 = `배율 × 도박기댓값`이며 허용 오차는 ±0.05다.
- 수식어의 등급 차이는 단순 배율이 아니라 전술의 강도·조합 수와 명시 잉크 비용으로 표현한다.
- 동사는 배율이 아니라 깡수치를 내므로 **등급이 곧 계수**다. 전체 적중(`aoe=all`)은
  계수를 ×0.7로 깎아서 산다(영웅 ×2 → ×1.4).
- 전설은 규칙 카드(문장부호·무럭무럭·아이템) 전용이라 수치 예산이 없다.

### 노멀 정원 — 주어 1 · 수식 3 · 동사 3

초기 덱의 노멀은 **슬롯마다 기준 카드 몫만** 둔다. 노멀을 여러 장 두면 예산이 같아서
수치가 똑같은 쌍둥이가 생기고(`어제의 나는 = 나도 = 오늘의 나는 = ×1.20`,
`막았다 = 지켰다`), 그 순간 등급 표기가 예산을 설명하지 못한다.

- 주어 1장 — `나는`
- 수식 3장 — 기본 전술마다 하나(`힘껏`=관통 · `다정히`=배율·카운터 · `살짝`=선공)
- 동사 3장 — 행동마다 하나(`때렸다`·`막았다`·`감쌌다`)

나머지는 지우지 않고 **예산이 큰 등급으로 올려** 성향을 갈랐다. 정원은 `COMMON_QUOTA`로
검사한다.

### 같은 예산, 다른 성향

주어는 배율/도박으로 예산을 나누고, 수식은 전술 기능만 가진다. 희귀 주어 예산 1.60은
도박 사다리로 갈라 놓았다 — 확률이 낮을수록 배율이 크다.

| 주어 | 표기 |
|---|---|
| 나만은 | `배율 ×1.60` (확정) |
| 어제의 나는 | `75% 확률로 배율 ×1.80` |
| 나도 | `60% 확률로 배율 ×2.00` |
| 다친 나는 | `50% 확률로 배율 ×2.20` |
| 겁먹은 나는 | `40% 확률로 배율 ×2.50` |
| 오늘의 나는 | `30% 확률로 배율 ×3.00` |

도박 표기는 **저점을 적지 않는다** — `variance_lo`는 항상 1이므로 `×2.50 / ×1.00`은
"절반은 손해"처럼 읽힌다. `note`는 `40% 확률로 배율 ×2.50` 형식으로 쓰고, 화면도
`wordValueLines()` 한 곳에서 같은 문장을 만든다(체인·카드 상세·보상 공용).

동사도 `공격 ×1`처럼 배율·방어와 같은 형식으로 적는다 — "적을 공격"은 수치가 아니다.

에픽은 초기 덱에 넣지 않는다(보상으로만) — 1일차에 잭팟이 열리면 곡선이 무너진다.

### 태그로 갈리는 값은 화면에 내건다

동사처럼 등급이 곧 계수인 슬롯은 같은 등급의 수치가 같다(`지켰다`·`웅크렸다` 모두 ×1.5).
실질 차이는 **태그가 여는 관용구 수**인데 이건 카드에 안 적히는 숨은 값이었다.
그래서 카드 상세가 「여는 맥락」 목록(관용구 이름·배수·짝이 될 카드)을 그대로 보여 준다.
새 카드를 넣을 때 태그로만 세게 만들었다면, 그 태그가 실제로 어떤 관용구에 걸리는지
`combos.csv`를 함께 확인한다.

CSV를 수정한 뒤 다음 명령으로 타입이 있는 런타임 데이터를 다시 만든다.

## 잉크 비용

일반 런 카드는 `card_tactics.csv`에 비용을 명시해 반복강화로 수치가 올라도 비용이
갑자기 변하지 않는다. 기본 6, 남은 잉크 이월 최대 2, 체력 초과 집필 최대 2로 한 문장의
절대 상한은 10이다. 비용대는 주어 0·2·3, 수식어 1·2·3, 동사 2·3·4를 기준으로 한다.
주어와 수식어는 문장의 성향을 고르는 단계라 합산 지출을 억제하고, 공격 횟수·대상 수·관통처럼
행동 강도를 직접 올리는 값은 고비용 동사에 집중한다. 수식어가 행동을 두 번 발동시키는 예외는
각 발동 위력을 낮춰 총량을 제한하고 영웅 등급·비용 3처럼 후반 선택으로 둔다. 최종 지출은 동사
선택에서 닫는다.

```bash
npm run data:generate
```

`dev`, `type-check`, `sweep`, `build`도 실행 전에 이 변환을 자동 수행한다. 생성된
`src/data/generated/sentenceData.ts`는 직접 편집하지 않는다.
